# 2025-04-24 Log — Master Data: Users & Permissions

## 📌 Context
Received requirement from my boss to design a permission system for user management.  
Director must be able to assign permissions, and employees should only access system areas relevant to their work.  
Company hierarchy has three fixed roles: Director, Manager, Staff.  
IT team will create initial accounts and send login details to users.

## ⚠️ Challenge
- RBAC with only 3 fixed roles is too rigid.  
- Employees in the same role would have broad access, which conflicts with the requirement for department/individual restrictions.

## 🔧 How I Handled It
- Analyzed the limitations of RBAC.  
- Proposed Attribute-Based Access Control (ABAC) or group-based permissions for flexibility.  
- Designed system to auto-create default permission groups when new modules (e.g., Sales, Production) are added.  
- Reviewed code for profile access and confirmed Director/group permissions logic.

## 📊 Outcome
- Permission model shifted to group/attribute-based design.  
- Director retains authority but system remains flexible.  
- Supports scalability and prevents overexposure of system functions.

## 🎯 Lessons Learned
- Fixed roles alone are insufficient for complex organizational structures.  
- Group/attribute-based permissions provide necessary flexibility.  
- Default group creation reduces Director’s workload and ensures consistency.

## 📌 Next Steps
- Implement group-based permission model.  
- Test with Sales and Production modules.  
- Document workflows for Director and IT onboarding.
