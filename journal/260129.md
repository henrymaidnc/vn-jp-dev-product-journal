# 2026-01-30 Log - Special Character Encoding Issue

## 📌 Context
Implementation of the Copy Function in master data modules (Company and Employee). Also encountered issues related to character encoding with Japanese keyboards.

## 👥 Stakeholders
- Internal development team  
- End users creating records in the system  

## ⚠️ Problem
1. Initially implemented the copy function with incorrect logic — copying the entire record instead of allowing selective field copying.  
2. Encountered issues with half-width (`@`) and full-width (`＠`) characters. The system only tracked half-width characters, which prevented end users from creating records correctly when using Japanese keyboards.  

## 🔧 How I Handled It
- Discussed with the team to clarify requirements.  
- Adjusted the copy function to be **abstract**, allowing overrides in each model so only the required fields are copied.  
- Investigated the character encoding issue and identified the difference between half-width and full-width characters.  

## 🛠️ Environment
- Master Data modules (Company, Employee)  
- Common service for copy logic  
- Windows OS with Japanese keyboard input  

## 📊 Outcome
- Copy function logic corrected: now supports selective field copying with overrides.  
- Identified root cause of character input issue, preventing further confusion for end users.  

## 🎯 Lessons Learned
- Always clarify requirements with the team before implementation.  
- Copy functions should be designed abstractly to allow flexibility across different models.  
- Pay attention to localization issues such as half-width vs. full-width characters, especially when supporting Japanese input.  

## 📌 Next Steps
- Finalize and test the abstract copy function across all relevant modules.  
- Implement validation or normalization for character input to avoid similar issues in the future.  
- Share findings with the team to improve awareness of localization challenges.
