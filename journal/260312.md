The goal was to clarify the domain structure of the system and improve how modules are organized so the system can scale and support multiple departments.

At the same time, I also encountered a networking issue related to WSL and local development environment configuration.

Internal development team.

Potentially affected departments:

For the networking issue, it also affects anyone accessing the development server on the local network.

---

## ⚠️ Problem

### 1. Architecture organization
Several architectural questions appeared during the review:

- Whether **Customer** should be treated as a core domain entity.
- Whether **Quotation** should remain inside the **Sales app** or become a shared module.
- How to better separate backend and frontend responsibilities during development.

### 2. Local network IP conflict
While exposing the WSL development server to the local network, I configured a **static IP address** on my machine.

Later, another device on the same network automatically obtained the same IP address from DHCP, which caused an **IP address conflict**.

Symptoms included:
- The machine could not access the network.
- Network connection failed due to **duplicate IP detection**.

---

## 🔧 How I Handled It

### Architecture decisions

1. **Customer as a core entity**
   - Customer owns related objects such as:
     - departments
     - contacts
     - notes
     - tags
     - activities
   - These should belong to the Customer domain.

2. **Quotation as a standalone module**
   - Quotation should not be limited to the Sales app.
   - It should be extracted into a separate Django app so multiple departments can reuse it.

3. **Backend / Frontend task separation**
   - Backend engineer focuses on:
     - business logic
     - models
     - views
     - validation
   - Frontend engineer focuses on:
     - templates
     - UI
     - JavaScript interactions

This separation makes debugging and issue tracking easier.

---

### Network issue solution

Steps taken to resolve the IP conflict:

1. Identified that another device had obtained the same IP address.
2. Released the conflicting IP from the other machine using DHCP renewal.
3. Restored normal network connectivity.

Key takeaway:
- Hardcoding an IP address on a local network can cause conflicts if the DHCP server assigns the same address to another device.

Better approaches include:
- Reserving the IP in the router DHCP configuration.
- Using dynamic IP with port forwarding instead of manually assigning a static address.

Key results:

---

## 🎯 Lessons Learned

Important insights:

- Core business concepts should be modeled as **domain entities**, not just tables.
- Shared functionality across departments should be separated into **independent modules**.
- Static IP addresses on a DHCP network can cause conflicts if not properly reserved.
- It is safer to configure **DHCP reservation at the router level**.
